## 2. x86保护模式与地址转换基础

> 课件 第 81–85 页 · 讲解从 `06:08` 开始

### x86 保护模式与地址转换基础

x86 体系结构从 8086、8088 开始持续演进。由于 Intel 承诺硬件升级后仍可向下兼容并运行旧软件，因此在硬件设计中做了大量适配与妥协。传统实模式后来被虚拟 8086 模式取代，目前 x86 的主要工作模式包括 `▶ 06:08`：

- **实模式（Real Mode）**
- **保护模式（Protected Mode）**
- **虚拟 8086 模式（Virtual 8086 Mode）**

本章重点关注保护模式下的寻址、地址保护以及分页地址转换机制。

---

### 保护模式下的寻址方式

保护模式下的寻址采用 **“段基地址 + 偏移地址”** 的基本形式。与实模式下段寄存器直接给出段基址不同，保护模式中需要借助：

- **段选择符（Segment Selector）**
- **段描述符（Segment Descriptor）**

完成段信息的查找与保护检查。

寻址时，段寄存器中保存的是段选择符；系统根据段选择符在相应描述符表中找到段描述符，再从段描述符中取得段基地址、段限长和访问权限等信息，最后与偏移地址结合形成地址。

老师以中断处理程序的查找为例说明：查找中断处理程序时，需要先通过 **中断描述符表（IDT）** 获取对应的段选择符，再根据段选择符找到段描述符，从段描述符中取出段基地址，最后结合偏移地址得到最终处理程序地址 `▶ 07:52`。

学习这一部分时需要重点思考以下问题：

1. x86 提供哪几种工作模式？
2. 保护模式下如何完成寻址？
3. 地址保护如何借助段描述符等机制完成？
4. 操作系统如何绕开或弱化 x86 的分段机制？

---

### 段页式地址转换

x86 保护模式下的地址转换可以分为两个阶段：

```text
逻辑地址 → 段式转换 → 线性地址 → 页式转换 → 物理地址
```

- **逻辑地址（Logical Address）**：由段选择符和段内偏移组成。
- **线性地址（Linear Address）**：逻辑地址经过分段机制转换后得到。
- **物理地址（Physical Address）**：线性地址经过分页机制转换后得到。
- 如果未开启分页机制，线性地址可直接作为物理地址使用。

Windows 为了绕开 x86 复杂的段页式设计，采用 **单段设计**：各段的基地址基本相同，使分段机制退化为一个大的线性地址空间，从而主要依赖分页机制完成虚拟内存管理。这样相当于“一个大分页”，不存在多段空间之间的复杂区分问题 `▶ 07:52`。

因此，在 Windows 的典型地址转换流程中：

1. 逻辑地址先经过单段式转换得到线性地址；
2. 开启分页机制后，再由分页硬件将线性地址映射为物理地址 `▶ 10:07`。

---

### 与虚存管理相关的控制寄存器

x86 中与虚拟内存和地址转换密切相关的控制寄存器主要包括：

| 寄存器 | 作用 |
|---|---|
| **CR0** | 包含控制处理器工作模式的标志位，其中包括分页机制使能位 |
| **CR2** | 页故障线性地址寄存器，发生缺页异常时记录触发异常的线性地址 |
| **CR3** | 页目录基址寄存器，指向当前进程页目录或顶层页表的起始物理地址 |
| **CR4** | 包含若干扩展机制使能位，支持更复杂的分页和处理器特性 |

系统启动时会对这些控制寄存器进行初始化设置。**CR3 指向页表的起始地址**，是分页地址转换的重要入口 `▶ 10:07`。

> **老师强调**：**CR2 很重要**。发生页错误时，CR2 用于保存引起异常的线性地址，操作系统需要根据该地址判断缺页原因并完成处理 `▶ 10:07`。

---

### x86 页目录项与页表项

x86 分页机制通过多级页表完成线性地址到物理地址的转换，其中典型表项包括：

- **页目录项 PDE（Page Directory Entry）**
- **页表项 PTE（Page Table Entry）**

页目录项用于定位下一级页表，页表项用于定位最终的物理页帧。二者都不仅包含物理页帧号或页表物理地址，还包含一组控制和状态位。

#### x86 32 位页表项中的常见字段

| 字段 | 含义 |
|---|---|
| **P（Present）** | 页或页表是否在物理内存中 |
| **R/W（Read/Write）** | 读/写权限，控制页面是否可写 |
| **U/S（User/Supervisor）** | 用户态/内核态访问权限 |
| **PWT（Page-Level Write-Through）** | 页表或页面的写直达缓存策略 |
| **PCD（Page-Level Cache Disable）** | 是否禁止缓存 |
| **A（Accessed）** | 访问位，页面或页表被访问时由硬件设置 |
| **D（Dirty）** | 脏位，页面被写入时由硬件设置，主要用于 PTE |
| **PS（Page Size）** | 大页标志，用于选择 4 KB 或更大页面 |
| **G（Global）** | 全局页标志，任务切换时可避免该页从 TLB 中清除 |
| **PFN（Page Frame Number）** | 物理页帧号，用于给出物理页或页表地址 |
| **Avail** | 保留给操作系统使用的字段 |
| **0** | 必须为 0 的保留位 |

课件同时给出了 **AMD x64 体系结构中的页表项格式**。在 64 位体系结构中，页表项宽度扩展为 64 位，可以表示更大的物理地址空间，并增加了如 **XD（Execute Disable，禁止执行）** 等权限位。

---

### Core i7 多级页表项结构

在 Core i7 的多级页表中，第 1 至第 3 级页表项用于引用下一级的 4 KB 子页表。其高位字段为 **页表物理基地址（Page table physical base address）**，低位为各种属性位。

#### 有效页表项：`P = 1`

当 `P = 1` 时，表示对应的子页表存在于物理内存中。页表项中的主要字段如下：

| 字段 | 含义 |
|---|---|
| **P** | 子页表是否存在于物理内存中；`1` 表示存在，`0` 表示不存在 |
| **R/W** | 所有通过该页表项可达页面的只读/读写权限 |
| **U/S** | 所有通过该页表项可达页面的用户态/内核态访问权限 |
| **WT** | 子页表采用写直达还是写回缓存策略 |
| **CD** | 是否禁用子页表的缓存 |
| **A** | 访问位，读或写时由 MMU 设置，由软件清除 |
| **PS** | 页面大小，可为 4 KB 或 4 MB；该位只在第 1 级 PTE 中定义 |
| **G** | 全局页，任务切换时不从 TLB 中淘汰 |
| **Page table physical base address** | 页表物理地址的高 40 位，强制页表按 4 KB 对齐 |
| **Unused** | 未使用字段 |

其中，页表物理基地址占据物理页表地址的最高 40 位。由于页表要求 4 KB 对齐，地址的低 12 位为 0，因此这些低位可用于存放权限和状态信息。

#### 无效页表项：`P = 0`

当 `P = 0` 时，表示对应页表或页面当前不在物理内存中。此时表项其余位可由操作系统使用，例如记录该页在磁盘上的位置。

这种情况下访问对应地址通常会引发页故障，操作系统可根据故障地址和页表项内容判断：

- 页面是否被换出到磁盘；
- 页表是否尚未创建；
- 访问是否违反权限；
- 是否需要分配物理页并从磁盘读入数据。

64 位页表项还包含：

- **XD（Execute Disable）**：禁止执行位，用于防止数据页被当作代码执行；
- **Available for OS**：供操作系统自定义使用，例如保存页面在磁盘上的位置等信息。

---

### 本章小结

保护模式下，x86 原本通过分段机制将逻辑地址转换为线性地址，再通过分页机制将线性地址转换为物理地址。Windows 采用单段模型弱化分段，使虚拟内存管理主要建立在分页机制之上。

分页转换依赖 CR3 指向的多级页表；CR2 在缺页异常时保存故障线性地址，是操作系统处理页错误的关键寄存器。PDE 和 PTE 除了保存物理地址或物理页帧号，还通过 P、R/W、U/S、A、D、PS、G、XD 等字段完成存在性、权限、访问统计、页面大小、全局映射和执行保护等管理功能。

## 3. Windows内存管理器及其关键组件

> 课件 第 86–91 页 · 讲解从 `12:38` 开始

### 内存管理器在 Windows 体系结构中的位置

Windows 的核心功能主要位于系统目录下的内核文件 **`Ntoskrnl.exe`** 中，内存管理器（Memory Manager，Virtual Memory Manager）也位于该文件内，是 Windows 内核的重要功能模块之一`▶ 12:38`。

从整体内核结构看：

- 最贴近硬件的是 **HAL（Hardware Abstraction Layer，硬件抽象层）**，用于屏蔽硬件细节。
- HAL 不能完全屏蔽所有硬件交互，因此内核其他部分仍可能包含少量与硬件相关的代码。
- 内核内部包含多个功能模块，内存管理器负责虚拟内存、物理页框、缺页、页面置换和后备存储等管理工作`▶ 12:38`。

---

### 内存管理器的主要组成

Windows 内存管理器并不是单一函数或单一模块，而是由一组内核服务、陷阱处理程序和若干系统线程共同组成。

| 组成部分 | 主要职责 |
|---|---|
| 一组执行体系统服务程序 | 提供虚拟内存的分配、回收、管理等服务 |
| 页面错误陷阱处理程序 | 处理硬件检测到的内存管理异常，如缺页、写只读页等 |
| 工作集管理器 `MmWorkingSetManager` | 空闲内存不足时执行工作集修整、老化和脏页写回等策略 |
| 进程/栈交换器 `KeSwapProcessOrStack` | 完成进程和内核线程堆栈的换入、换出 |
| 修改页面写出器 `MiModifiedPageWriter` | 将页文件后备的“脏”页写回页文件 |
| 映射页面写出器 `MiMappedPageWriter` | 将映射文件中的“脏”页写回磁盘文件 |
| 零页线程 `MmZeroPageThread` | 将空闲链表中的页框清零，准备全零页 |

---

### 执行体系统服务程序

内存管理器提供一组可调用的执行体系统服务，用于虚拟内存的分配、回收和管理。大多数服务以两种形式对外呈现：

1. **Win32 API**：供用户态应用程序调用；
2. **内核态设备驱动程序接口**：供设备驱动程序等内核组件调用。

其中还存在大量未写入官方文档、未公开的内核接口，这类接口一般不对普通用户开放，主要供驱动程序使用`▶ 16:19`。

---

### 页面错误陷阱处理程序

当硬件检测到页面错误（Page Fault，也称页失效或缺页异常）时，CPU 会从用户态陷入内核态，由内存管理器中的 **页面错误陷阱处理程序** 处理。该处理程序也可理解为缺页处理程序`▶ 13:58`。

它负责解决硬件检测到的内存管理异常，例如：

- 页表项有效位为 0，目标页面当前不在物理内存中；
- 对只读页面执行写操作；
- 访问权限不满足；
- 需要为虚拟页分配物理页框；
- 需要从磁盘上的后备存储把数据装入内存。

处理程序会根据异常的具体类型选择相应处理方法，而不是把所有 Page Fault 都简单视为“缺页”`▶ 13:58`。

> **老师强调**：要把异常触发条件对应到页表项的数据结构。页表项至少包含 6 个常用标志位，这些标志位与页面置换、是否触发内核陷入等机制直接相关`▶ 13:58`。

---

### Windows 与内存管理相关的系统线程

Windows 中除普通用户线程外，还有许多运行在内核态、可参与调度的系统线程。Windows 调度共有 32 个优先级：

- **优先级 0**：最低优先级，对应系统的零页线程；
- **优先级 1～15**：普通用户线程的优先级范围；
- **优先级 16～32**：系统线程的优先级范围`▶ 17:57`。

#### 零页线程 `MmZeroPageThread`

零页线程优先级为 **0**，负责把空闲链表中的页框清零，为系统提前准备内容全为 0 的空闲物理页框`▶ 17:57`。

其作用包括：

- 保证新分配给进程的页面不会泄露旧页面中的残留数据；
- 在系统空闲时利用最低优先级完成清零工作；
- 需要零页时可以更快地直接获得已经清零的页框。

#### 工作集管理器 `MmWorkingSetManager`

Windows 借用了 1968 年 Denning 提出的工作集概念，但没有完全使用原始工作集模型，而是保留了“工作集”这一名称。在 Windows 中，工作集基本可理解为进程当前驻留在物理内存中的页面集合，即驻留集`▶ 20:05`。

虚拟内存系统理想情况下应始终保持一定数量的空闲物理页框，因此不能等物理内存完全耗尽后才开始置换，而应提前进行页面管理。

当空闲内存低于设定阈值时，工作集管理器启动，执行以下内存管理策略：

- 工作集修整；
- 页面老化；
- 选择适合移出内存的页面；
- 将已修改页面写回磁盘；
- 配合其他系统线程和内核服务完成页面回收`▶ 20:05`。

#### 修改页面写出器 `MiModifiedPageWriter`

当读入内存的数据被修改后，对应页面成为“脏”页。修改页面写出器负责把这类脏页写回到适当的 **页文件** 中`▶ 19:47`。

写回可以按系统策略定期执行，也可以在内存压力较大时按需执行。

#### 映射页面写出器 `MiMappedPageWriter`

映射页面写出器也负责写回脏页，但它处理的是 **映射文件中的页面**。如果页面的后备存储是磁盘上的普通文件，则该文件中的脏页由映射页面写出器写回原磁盘文件。

#### 进程/栈交换器 `KeSwapProcessOrStack`

进程/栈交换器负责完成进程和内核线程堆栈的换入、换出操作，使暂时不运行的进程或内核栈可以移出内存，在需要时再换回。

---

### Windows 虚拟地址空间的构成

虚拟内存是操作系统设计出来的虚拟地址空间，并不是真实的物理内存。系统通过虚拟地址空间、物理内存和页表共同描述进程的内存状态`▶ 22:27`。

一个进程的虚拟地址空间通常由以下内容组成：

| 区域类型 | 内容来源或用途 |
|---|---|
| EXE 代码区 | 来自可执行文件本身的代码 |
| EXE 静态数据区 | 来自可执行文件的静态数据 |
| DLL 代码区 | 来自动态链接库的代码 |
| DLL 静态数据区 | 来自动态链接库的静态数据 |
| 动态分配数据区/堆 | 程序运行时通过堆等方式动态申请 |
| 操作系统支持区域 | 操作系统代码、数据及内核支持结构 |
| 栈等运行时区域 | 线程运行所需的栈等内存区域 |

以 Linux 中类似机制作为类比，进程控制块 `task_struct` 中的 `mm` 字段指向 `mm_struct`，`mm_struct` 再串联多个 `vm_area_struct`。每个 `vm_area_struct` 描述一段连续虚存区域，并对应其磁盘来源或运行时用途`▶ 22:27`。

---

### 磁盘上的后备存储

虚拟地址空间中的页面不一定长期位于物理内存中。当页面被换出时，必须在磁盘上有相应的后备存储。Windows 中主要包括两类：

1. **区域（Section）/映射文件**
   - 通常对应 EXE、DLL 或其他被映射的普通文件；
   - 文件中的代码和数据可以按页读入内存；
   - 若映射文件页面被修改，脏页可写回原文件。

2. **页文件（Pagefile）**
   - 用于保存运行时动态生成、原本没有对应磁盘文件的页面；
   - 例如堆等匿名内存页面；
   - Windows 可以配置多个页文件，一个写满后可继续使用下一个`▶ 25:06`。

在 Linux 中，与页文件作用相近的是匿名页及交换机制相关概念；术语不同，但本质上都是为没有普通文件后备的匿名页面提供磁盘后备空间`▶ 25:06`。

---

### 32 位 Windows 虚拟地址空间布局

在 32 位系统中，虚拟地址空间总量为 4GB，通常按进程用户空间和内核空间划分：

- 常规划分：用户空间 **2GB**，内核空间 **2GB**；
- 可选配置：用户空间 **3GB**，内核空间 **1GB**。

这种划分并非固定不变。对于数据库等需要较大用户虚拟地址空间的应用，可以采用 3GB 用户空间配置，但相应地内核空间会缩小到 1GB`▶ 26:29`。

所有进程的内核空间内容基本一致，每个进程共享同一份操作系统内核副本；不同进程主要在用户空间和页表映射上存在差异`▶ 29:24`。

### 进程页表和页目录的虚拟映射

本章重点关注 Windows 内核空间中用于进程页表和页目录的区域。

在 32 位 Windows 中，内核会在虚拟地址空间中划出一块 **4MB 区域**，专门用于映射当前进程的页表和页目录，地址范围约为：

```text
C0000000 ~ C003FFFFF
```

教材标注可能存在轻微偏移，复习时以该地址范围本身为准`▶ 27:52`。

其组织方式如下：

- 创建进程时，内核同步创建该进程的页目录和一级页表；
- 一级页表创建时会在物理内存中分配页框；
- 页目录或一级页表的起始物理地址保存在进程控制块中；
- 当进程被调度到 CPU 上运行时，该地址被装入 x86 的 **CR3 寄存器**；
- 分散存放在物理内存中的页表，通过这 4MB 内核虚拟区域建立可访问的映射；
- 操作系统部分对应的页表在各进程间全局共享；
- 各进程用户空间对应的页表互不相同`▶ 29:24`。

地址转换时，CPU 使用 CR3、页目录和页表完成虚拟地址到物理地址的转换，并用 **TLB（快表）** 缓存常用地址转换结果，其基本原理与通用分页机制一致`▶ 29:24`。

## 4. Windows缺页异常类型与处理流程

> 课件 第 97–100 页 · 讲解从 `32:31` 开始

### 地址转换与有效/无效页表项

Windows 在 x86 上采用两级页表结构完成虚拟地址到物理地址的转换：

- 第一级是**页目录（Page Directory, PD）**，其中的表项称为 **PDE（Page Directory Entry）**。
- 第二级是**页表（Page Table, PT）**，其中的表项称为 **PTE（Page Table Entry）**。
- PDE 和 PTE 的**最低位是有效位（Valid/Present）**：
  - 为 `1`：表示该页映射到了物理内存，地址转换有效；
  - 为 `0`：表示对应 PTE/PDE 无效，页面当前不能直接访问。

当虚拟页位于物理内存中时，相应的 PDE、PTE 都有效。CPU 根据页目录和页表中的信息自动完成虚拟地址到物理地址的转换，这一过程不需要操作系统介入；TLB 还可以缓存地址转换结果，进一步提高转换速度`▶ 32:31`。

如果要访问的虚拟页不在物理内存中，则对应的 PTE 无效，最低位为 `0`。此时 CPU 无法完成正常地址转换，会引发页面错误异常。**有效 PTE 的格式由硬件页表机制决定，而无效 PTE 的具体格式由操作系统定义**，操作系统可以利用无效 PTE 中的不同编码表示多种异常原因。

> **老师强调**：要结合页表项数据结构理解缺页逻辑。页表项中各标志位非常重要，考试常考，必须牢记有效位、读写位、用户/内核模式位、引用位（R/A 位）、脏位（D/M 位）等的作用；并且只有有效位为 `1` 时，页框号 PFN 才有效`▶ 36:07 · 38:44`。

### Windows 中的保留与提交

Windows 虚拟地址空间管理中有两个核心概念：

| 概念 | 含义 |
|---|---|
| **保留（Reserve）** | 在进程虚拟地址空间中预先划定一段地址范围，确定起始地址和结束地址，相当于建立了一段虚拟内存区域（vm area） |
| **提交（Commit）** | 页面真正获得可用的物理存储支持，内容可以进入物理内存；访问时可根据需要从磁盘对象等后端读入 |

页面被保留时，只是在虚拟地址空间中占好了位置，并不代表页面内容已经在物理内存中。页面被提交后，也可能因为页面置换等原因暂时不在进程工作集中。Windows 与 Linux 的术语和函数名称不同，但核心虚拟内存管理逻辑相似：保留负责划分地址范围，提交才表示页面获得实际存储支持`▶ 35:19 · 36:07`。

### 页面失效：无效 PTE 对应的常见情况

Windows 中 PTE 无效并不只表示“页面尚未从磁盘读入”。无效 PTE 可用于编码多种页面失效原因。

#### 1. 所引用的页面没有被提交

页面可能已经被保留，但尚未提交，因而不在内存中。此时对应页表项已经能够表示该虚拟地址区域，但 PTE 最低有效位为 `0`。

这是最常见的缺页情况之一。例如创建进程时，系统已经按照代码段 text 的大小在虚拟地址空间中划分好范围，并建立相应页表项，但这些页表项的有效位最初均为 `0`，代码页尚未真正载入物理内存；只有执行到相应代码时才会通过缺页异常调入`▶ 36:07`。

#### 2. 违反页面访问权限

当访问方式不符合页面权限时，也会引发页面错误，例如：

- 对只读页面执行写操作；
- 用户态程序非法访问内核空间；
- 其他不符合 PTE 中读写位、用户/内核模式位等权限设置的访问。

这类异常不一定是“页面不在内存”，而是访问权限检查失败。

#### 3. 修改具有写时复制属性的私有共享页面

通过映射建立的页面可以带有共享或私有属性。某些页面初始时允许多个进程共享同一份物理页，以节省内存；但当某一方试图写入该页时，必须为其复制一份私有副本，这就是**写时复制（Copy on Write）**。

因此，修改一个私有的写时复制页面时，会触发缺页异常。操作系统在异常处理中完成复制、重新建立映射，然后让写操作重新执行。老师称这类页面为“私有共享”页面：初始内容可以共享读取，一旦写入就不再共享`▶ 37:25`。

#### 4. 需要扩大栈

当进程栈向低地址或高地址增长并触及尚未分配的栈页时，需要触发异常，由操作系统分配新的栈页并扩展栈空间。

#### 5. 所引用的页已经提交但尚未映射，或曾经被移出工作集

一个页面已经提交，并不意味着它当前一定映射在进程的工作集中。Windows 可在物理内存紧张时，由工作集管理器根据页面置换算法选择牺牲页：

1. 将选中页从所属进程的页框集合（工作集）中移出；
2. 放入空闲页框集合或系统的页缓冲中；
3. 将对应 PTE 的有效位从 `1` 改为 `0`；
4. 页面内容本身暂不修改，也不一定立即写回磁盘。

之后如果进程再次访问该页，操作系统发现无效 PTE 中记录的状态后，可能只需：

- 将 PTE 有效位从 `0` 改回 `1`；
- 把原页框重新挂回该进程的工作集；
- 恢复映射。

若该页内容仍保存在内存页缓冲中，就不需要重新从磁盘读入，从而降低缺页处理开销`▶ 38:44`。

#### 6. 请求一个零页面

当程序第一次访问需要初始化为全零的匿名页面时，也会触发缺页异常。操作系统可以分配一个零页面，或将页面清零后建立映射，以保证新页面内容符合零初始化要求。

### Windows 缺页异常的硬件触发过程

当指令访问某个虚拟地址时，CPU 会自动通过页目录和页表进行地址转换：

1. 根据虚拟地址找到页目录项 PDE；
2. 根据 PDE 找到对应页表；
3. 根据虚拟地址找到页表项 PTE；
4. 检查 PTE 是否有效以及访问权限是否满足。

如果 CPU 在转换过程中发现 PTE 或 PDE 无效，或访问违反权限，就会引发 **Page Fault**，即页面错误异常，也称缺页异常或缺页中断。其异常中断号为：

- 十六进制：`0xE`
- 十进制：`14`

在 x86 架构中，中断向量表前若干项由硬件体系结构固定定义，`0xE` 即对应页面错误异常`▶ 43:01`。

发生页面错误时，CPU 会自动完成两项关键准备工作：

- 将引发异常时访问的虚拟地址保存到 **CR2 寄存器**；
- 根据中断号 `0xE` 在中断描述符表 IDT 中查找对应中断描述符，并根据描述符中的入口地址转入异常处理程序。

将错误虚拟地址放入 CR2，是硬件为内核执行软件异常处理所做的准备，使操作系统能够知道是哪一个地址导致了页面错误`▶ 44:06`。

> **老师强调**：异常处理流程前半段由硬件完成，后半段由软件完成。不要简单记成“硬件→软件→硬件”的随意切换；期中考试曾要求区分每个步骤属于硬件还是软件，需要完整掌握流程，而不能只记概念`▶ 44:33 · 45:12`。

### Windows 内核中的软件处理入口

Windows 中页面错误的中断处理入口为：

```text
ntoskrnl!KiTrap0E
```

整体调用关系可概括为：

```text
CPU 地址转换失败
    ↓
保存错误虚拟地址到 CR2
    ↓
通过 IDT[0xE] 找到入口
    ↓
ntoskrnl!KiTrap0E
    ↓
MmAccessFault
```

`KiTrap0E` 是操作系统提供的陷阱处理程序，它会进一步调用内存管理中的 **`MmAccessFault`** 完成实际判断和处理。

`MmAccessFault` 的主要工作包括：

1. 从 **CR2** 中取得引发异常的虚拟地址；
2. 根据该虚拟地址计算并定位相应的 PDE/PTE；
3. 分析无效 PDE/PTE 中由操作系统定义的编码和标志位；
4. 判断异常属于哪种情况，例如：
   - 页面未提交；
   - 权限冲突；
   - 写时复制；
   - 栈扩展；
   - 页面已提交但当前未映射；
   - 请求零页面；
5. 根据不同原因执行相应处理；
6. 处理成功后恢复导致异常的指令重新执行；若属于非法访问，则进行异常分发或终止相关进程。

### 本章小结

- 正常情况下，PDE/PTE 有效位均为 `1`，地址转换由 CPU 自动完成，操作系统不介入。
- PTE 有效位为 `0` 时，硬件触发 Page Fault，异常号为 `0xE`。
- CR2 保存导致页面错误的虚拟地址。
- 无效 PTE 的格式由操作系统定义，可表示多种页面状态和错误原因。
- Windows 缺页入口是 `ntoskrnl!KiTrap0E`，实际内存管理判断由 `MmAccessFault` 完成。
- 缺页不一定意味着必须从磁盘读盘；若页面仍保存在内存页缓冲中，恢复 PTE 和工作集映射即可。
- 页表项标志位及缺页处理中的软硬件分工是重点和考试常考内容。

## 5. 页目录自映射机制与PTE地址计算

> 课件 第 101–104 页 · 讲解从 `46:13` 开始

### 页目录（Page Directory, PD）

**页目录的概念与存放**
- 页目录是内存管理器创建的一张特殊页，用来映射一个进程中所有页表的位置。
- 在二级分页结构中，32 位系统共有 **1025 张页表**：1 张一级页表（即页目录）+ 1024 张二级页表。这些页表分散存放在物理内存中，只有页目录必然存在；二级页表按需分配，实际数量由进程代码决定，不会全部建立`▶ 46:13`。
- 页目录的物理地址保存在进程的内核进程对象 `KPROCESS` 中；进程不运行时也保存在 PCB 里，调度运行时装入专用寄存器`▶ 53:56`。

**硬件与内核访问方式的区别**
- 硬件通过虚拟页号（VPN）、物理页帧号（PFN）来访问页目录、页表和数据页：虚拟地址前 10 位查页目录得到页表，中间 10 位查页表得到 PTE，再由硬件完成地址转换`▶ 53:56`。
- 专用寄存器 **CR3**（x86）保存页目录的物理地址。
- 内核不能直接用物理地址去查页表，否则会增加寻址复杂度；内核必须**通过虚拟地址**访问页目录和页表，这正是自映射机制要解决的问题`▶ 47:25`。
- 在 x86 的 Windows 上，页目录除了由 CR3 指向外，还被映射到固定虚拟地址 **0xC0300000**。

### 为什么需要自映射机制

- Windows 把内存中实际存放的页表结构**反向映射**到内核虚拟地址空间的一段固定区域，使页目录和所有页表都出现在该区域内。这样不同进程虽然物理页表位置不同，但内核都能用统一的虚拟地址公式访问它们`▶ 48:29`。
- 缺页时，硬件把引发缺页的虚拟地址记录在 **CR2** 中；缺页处理程序拿到该地址后，无需硬件再查表，仅凭移位这种 O(1) 运算就能直接算出对应 PTE 的虚拟地址，然后修改其存在位（0/1 切换）等字段`▶ 48:29 · 50:08 · 1:12:30`。
- 所有操作系统都有类似需求，Windows 采用的是"自映射"方案；Linux 的页表映射设计与此不同`▶ 48:29 · 50:42`。

### 4MB 映射区与"重叠一页"

- Windows 32 位内核虚拟地址空间中，用 **0xC0000000 ～ 0xC0400000 这 4MB** 区域存放页表映射，即 PTE 基地址区域`▶ 50:42`。
- 4MB 恰好只能容纳 **1024 个页**，但物理上共有 **1025 个页**需要映射（1 页目录 + 1024 页页表）。根据鸽巢原理，必然要有一个位置发生重叠`▶ 50:42 · 1:04:59`。
- 多出的那一页正是页目录，解决办法是：**让页目录与 1024 个二级页表中的某一个页表位置重叠**放置。该重叠位置是预先确定好的`▶ 50:42 · 1:04:59`。
- 普通区域对应 1024 个正常页表，其中有一个页表页对应的就是页目录本身；于是页目录在整个虚拟空间中既作为一级页表存在，又通过重叠占据了一个"页表页"的位置，其余页表项映射到其他位置，互不影响`▶ 1:08:36 · 1:11:39`。

### 自映射位置 0xC0300000 的确定

32 位虚拟地址划分为三段：

| 位段 | 位数 | 含义 |
|---|---|---|
| 高 10 位（bit 31–22） | 10 | 页目录索引（PDI） |
| 中 10 位（bit 21–12） | 10 | 页表索引（PTI） |
| 低 12 位（bit 11–0） | 12 | 页内偏移 |

重叠位置的选择由该地址结构决定`▶ 1:06:10`：

- 选定 **0xC0300000**（大致在 C0000000～C0400000 区间的 3/4 处）。
- 将 0xC0300000 右移 22 位取出页目录索引：`0xC0300000 >> 22 = 0x300`。
- 该地址的关键特征是：**页目录索引与页表索引数值相等，都是 0x300**`▶ 1:08:36`。
- 于是页目录中第 0x300 项（自映射 PDE）指向的物理页帧，恰好就是页目录自身的起始物理页（即 CR3 的内容），从而实现"页目录映射到自身"`▶ 1:08:36`。
- 推广来说，内核空间中凡是"高 10 位索引 = 中 10 位索引"的区间，理论上都可作为自映射 PDE 的位置；Windows 当前选定 0xC0300000 这一处`▶ 1:10:10`。
- 访问该位置时第一次查表查到的是页目录自身，需要再读取一次才能继续后续查询`▶ 1:10:10`。

### 课件中的两个示例地址

自映射关系可表示为：`PD[0xC0300000 >> 22] = PD`，即 `PD[0x300]` 指向 PD 自己。

- **虚拟地址 (a)：`(PTE *)(0xC0300C00)`**
  指向 `PD[0x300]`，即**自映射页目录项**本身。
- **虚拟地址 (b)：`(PTE *)(0xC0390C84)`**
  指向一个普通的 **PTE**，该 PTE 对应的原始虚拟地址是 **0xE4321000**。
  （这正体现了自映射后，可以用一个内核虚拟地址直接定位并修改任意用户虚拟地址的 PTE。）

### PDE / PTE 地址的计算宏

设 `PDE_BASE`、`PTE_BASE` 为页目录、页表映射区的基地址。

**MiGetPdeAddress(va)——给定虚拟地址 va，求其 PDE 的虚拟地址**

```c
((PMMPTE)(((((ULONG)(va)) >> 22) << 2) + PDE_BASE))
```

- 右移 22 位：取出高 10 位页目录索引；
- 左移 2 位：每项 4 字节，换算成字节偏移；
- 加上 `PDE_BASE` 得到该虚拟地址所对应的 PDE 地址`▶ 1:11:09`。

**MiGetPteAddress(va)——给定虚拟地址 va，求其 PTE 的虚拟地址**

```c
((PMMPTE)(((((ULONG)(va)) >> 12) << 2) + PTE_BASE))
```

- 右移 12 位：去掉页内偏移，取出整个 20 位虚拟页号；
- 左移 2 位：32 位系统中每个 PTE 占 4 字节，得到字节偏移（64 位系统每项 8 字节，应左移 3 位）；
- 加上 `PTE_BASE` 即得到目标 PTE 的虚拟地址`▶ 52:31`。

整个索引范围共有 1024（PDE 数）× 1024（每页表 PTE 数）= 1024² 个页表项，恰好铺满这 4MB 区域；算出 PTE 虚拟地址后，后续的物理映射由硬件自动完成`▶ 52:31`。

### 小结与扩展

- 自映射机制的核心目的是**便于内核计算地址**：缺页处理程序用移位宏即可由出错虚拟地址算出 PDE/PTE，进而修改页表项的存在位等`▶ 1:12:30`。
- 按需分配页采用的是直接映射，而本节介绍的自映射关键在于确定页目录与哪个页表位置重叠`▶ 52:16`。
- **64 位系统采用四级页表**，页表项更多、每项 8 字节，但仍然对第一级页目录做自映射，核心思想与 32 位系统一致`▶ 1:13:39`。

## 6. Windows工作集与页面置换管理

> 课件 第 105–109 页 · 讲解从 `1:14:43` 开始

### 工作集的基本概念

Windows 的驻留集等同于操作系统原理课中的工作集（Working Set）概念，指已经装入物理内存中的页面集合；一个虚拟页面只要被调入内存，就属于当前进程的工作集`▶ 1:14:43`。

在整个虚拟存储体系中，虚拟内存位于磁盘等外存上，物理内存中只保存进程当前使用的部分页面，这部分驻留页面构成工作集：

```text
虚拟内存（磁盘）  →  部分页面驻留  →  物理内存
                              ↑
                           工作集
```

### 工作集的分类

Windows 将工作集分为两类：

- **进程工作集**：为每个进程分配的一定数量的页框，保存该进程当前驻留在物理内存中的页面。
- **系统工作集**：为可分页的系统代码和系统数据分配的页框。

### 页面装入与置页策略

内存管理器主要采用以下方式管理页面装入：

- **请求式页面调度（请求调页）**：进程访问到尚未装入内存的页面时，才将相应页面调入。
- **簇方式装入**：一次不只装入一个页面，而是成簇地装入一批相关页面，以利用空间局部性、减少缺页次数。
- **置页策略**：选择页框时应尽量使 CPU 内存高速缓存不会产生不必要的震荡，即减少缓存频繁失效和反复置换。

### 工作集大小的变化

工作集不是固定不变的，而会随着进程的访问需求动态扩张、收缩，甚至发生迁移；在进程运行过程中可以监测到工作集大小的波动`▶ 1:15:41`。

工作集大小随时间的变化可分为：

- **过渡阶段**：进程刚开始执行或访问局部性区域发生变化时，工作集快速扩张或收缩。
- **稳定阶段**：当进程内存访问的局部性区域位置大致稳定时，工作集大小也大致稳定。

具体规律为：

1. 进程开始执行后，随着不断访问新页面，逐步建立较稳定的工作集。
2. 当内存访问的局部性区域位置大致稳定时，工作集大小也大致稳定。
3. 当局部性区域位置改变时，工作集快速扩张和收缩，过渡到下一个稳定值。

### 工作集的最小值与最大值

Windows 的工作集模型默认采用**动态构成**：在内存页框充足时，进程需要页面就为其分配页框；同时，系统为每个进程设置工作集的最小值和最大值，在内存资源紧张时作为控制阈值`▶ 1:17:00`。

| 界限 | 作用 |
|---|---|
| 最小值 | 内存紧张时也尽量保证进程保留的基本页框数 |
| 最大值 | 限制一个进程工作集可扩张到的页框上限 |

### 页面置换与工作集修整

Windows 的页面置换算法基于工作集模型，工作集由已经装入内存的页框组成。当系统可用页框数量降低到一定程度时，会启动工作集修整策略，动态调整各工作集的大小和构成。

触发与执行机制如下：

- 系统维护空闲页框“库存”。
- 当空闲页框数量低于设定阈值时，触发工作集回收；课堂中给出的阈值是**必须维持约 300 个空闲页框**`▶ 1:17:48`。
- 触发后，优先级为 **16** 的工作集管理器线程运行，回收各工作集超出上限的物理页，使空闲页框数量恢复到阈值以上`▶ 1:17:48`。

### 平衡集管理器

平衡集管理器线程负责周期性检查系统状态，并在需要时调用工作集管理器。它**每秒唤醒一次**，依次完成两类检查`▶ 1:18:54`：

1. 检查就绪队列中是否存在等待超过 **300 个时钟周期**、长期未被调度的饥饿线程。
2. 检查空闲页框库存是否不足；若不足，则调用工作集管理器执行页面回收。

系统会根据不同内存状态进行周期性调整：

- **大量可用内存**：允许工作集按需增长。
- **内存开始紧张**：开始限制或修整工作集。
- **内存紧缺**：积极回收超出限制的页框，补充空闲页框库存。

> **老师强调**：当空闲页框低于规定的约 300 个阈值时，会触发优先级为 16 的工作集管理器；平衡集管理器每秒唤醒，并检查饥饿线程和空闲页框库存，这些都属于 Windows 内存置换机制的核心逻辑`▶ 1:17:48 · 1:18:54`。

## 7. 用户空间虚拟内存分配与VAD

> 课件 第 110–114 页 · 讲解从 `1:20:10` 开始

### 用户空间内存分配方式

Windows 虚拟内存管理中，用户空间内存分配主要有三种方式：

1. **以页为单位的虚拟内存分配方式**
   - 函数：`Virtualxxx` 系列
   - 可执行文件的代码段、数据段都按页分配`▶ 1:20:10`

2. **内存映射文件**
   - 直接将磁盘文件映射到虚拟地址空间的指定位置`▶ 1:20:10`
   - 函数：`CreateFileMapping`、`MapViewOfFile`

3. **内存堆方法**
   - 函数：`Heapxxx`
   - 早期接口：`Localxxx` 和 `Globalxxx`

### 以页为单位的虚拟内存分配

#### 保留与提交两个阶段

在 32 位 Windows 中，进程用户地址空间范围为 `0x00000000 ~ 0x7FFFFFFF`。用户程序使用一段地址范围必须经过两个阶段：

- **保留（Reserve）**
  - 在虚拟地址空间中划定一段预留的地址范围，供线程将来使用
  - 对应 Linux 的 `mmap` 操作，Windows 中使用 `VirtualAlloc` 完成
  - 类似于订酒店时提前预定房间
  - 预留后可以选择提交或不提交；未提交的预留地址在页表中没有对应的有效映射项`▶ 1:21:28`

- **提交（Commit）**
  - 为已保留的地址空间分配实际的物理存储器
  - 提交时必须指出将物理存储器提交到何处以及提交多少
  - 提交页面在访问时会转变为物理内存中的有效页面
  - 后续发生缺页时再将内容从磁盘读入内存
  - 类似于办理入住、分配实际房间号`▶ 1:21:28`

#### 相关 API

| 功能 | 函数 |
| --- | --- |
| 保留/提交虚拟内存 | `VirtualAlloc`、`VirtualAllocEx` |
| 回收页面或释放地址空间 | `VirtualFree`、`VirtualFreeEx` |

程序可以首先保留地址空间，然后再向该地址空间提交物理页面。

### 为什么需要 VAD

使用 `VirtualAlloc` 可以在用户地址空间中保留或提交指定地址和大小的一段地址空间，但系统需要知道这段地址空间是否已经被分配（保留或提交）：

- **判断是否已提交物理内存**：理论上可以通过页目录和页表判断，但这样做很麻烦。
- **判断是否已被保留**：仅通过页目录和页表无法判断，因为保留但未提交的地址在页表中没有有效映射项。

> **老师强调**：由于未提交的预留地址无法通过页表、页目录获取状态，因此必须使用独立的数据结构来记录所有预留的地址区间`▶ 1:23:51`。

### 虚拟地址描述符（VAD）

对于每一个进程，Windows 的内存管理器维护一组**虚拟地址描述符（Virtual Address Descriptor, VAD）**，用来描述一段已被分配的进程虚拟空间的状态。

VAD 与 Linux 中的 **VMA（`vm_area_struct`）** 承载的信息基本一致，只是命名不同：

| 对比项 | Windows | Linux |
| --- | --- | --- |
| 描述结构 | VAD（虚拟地址描述符） | VMA（`vm_area_struct`） |
| 记录内容 | 虚拟地址范围、内存权限等属性 | 虚拟地址范围、内存权限等属性 |
| 组织结构 | 自平衡二叉树（AVL 树） | 链表 |
| 根的位置 | 保存在进程结构 `EPROCESS` 中 | 保存在进程控制块中 |

> **老师强调**：Windows 将 VAD 组织为 AVL 树，Linux 使用链表组织 VMA；两类结构的树根均存储在进程控制块中。Windows 的 `EPROCESS` 在功能上与 Linux 的 `task_struct` 完全等价`▶ 1:25:08`。

VAD 中的虚拟地址描述信息被构造成一棵**自平衡二叉树（AVL 树）**，以便提高地址区间的查找效率。

每个 VAD 主要描述以下信息：

- 虚拟地址范围
- 保护限制（内存访问权限）
- 是否可继承

例如，进程中可能存在如下 VAD：

| 虚拟地址范围 | 保护限制 | 继承 |
| --- | --- | --- |
| `0x20000000 ~ 0x2000FFFF` | 读/写 | 有 |
| `0x00002000 ~ 0x0000FFFF` | 只读 | 无 |
| `0x4E000000 ~ 0x4F000000` | 复制可写入 | 有 |
| `0x32000000 ~ 0x3300FFFF` | 只读 | 无 |
| `0x7AAA0000 ~ 0x7AAA00FF` | 读/写 | 无 |

因此，当系统需要判断某段虚拟地址是否已经保留或提交，以及其权限属性时，可以通过进程 `EPROCESS` 中的 VAD 树根，在 VAD 二叉树中高效查找对应地址区间。

## 8. 区域对象、内存映射文件与内存堆

> 课件 第 115–117 页 · 讲解从 `1:26:21` 开始

### 区域对象与内存映射文件

Windows 中的**区域对象（section object）**在 Win32 子系统中称为**文件映射对象**，它表示可以被两个或更多进程共享的内存块。区域对象不仅可以映射到磁盘上的普通文件，也可以基于页文件创建。

区域对象主要提供两类服务：

- **大数据流服务**：借助内存映射文件高效处理大文件；
- **内存共享服务**：让多个进程共享同一块内存。

> **老师强调**：Windows 的内存映射文件称为区域对象，其本质与 Linux 的内存映射机制相同，只是命名不同；它可以实现大文件快速处理和跨进程内存共享`▶ 1:26:21`。

#### 相关 API

- `CreateFileMapping`：创建区域对象（文件映射对象）。
- `MapViewOfFile`：将区域对象的一部分映射到进程地址空间，被映射的这一部分称为**区域视图（view）**，调用时可以指定映射范围。
- 当两个或多个进程对同一区域对象建立视图时，它们便共享该区域对象所对应的内存。

### 通过区域对象访问文件

使用区域对象可以把一个文件映射到进程的虚拟地址空间中。映射完成后，程序对文件的访问就像访问内存中的一个大数组，而不需要再显式调用文件的读、写操作。

例如，对一个存储了 1 亿个整数的文件进行排序时，可以先把该文件通过内存映射挂载到进程的虚拟地址空间，然后按照数组方式访问其中的数据，无需手动进行文件读写`▶ 1:26:21`。

其工作过程如下：

1. 程序访问映射后的地址；
2. 若访问的页面无效，即对应页面当前不在物理内存中，则触发**缺页中断（Page Fault）**；
3. 内存管理器自动把所需页面从映射文件读入物理内存；
4. 程序继续执行，对用户而言就像直接访问内存数组一样。

> **老师强调**：内存映射文件完全依托虚拟存储的缺页中断机制实现。访问内容不在内存时，系统会自动将对应页读入，用户无需关心文件 I/O`▶ 1:26:21`。

如果应用程序修改了映射页面中的内容，内存管理器会在页面进行常规调度时把修改写回映射文件。应用程序也可以主动调用 Win32 函数 `FlushViewOfFile` 刷新视图，将修改尽快写回文件。

### 多进程共享

当多个进程映射同一个区域对象或同一个文件映射对象时，它们共享同一份物理内存中的数据，而不是为每个进程分别保存完整副本。

> **老师补充**：如果多个进程共享同一个映射文件，内存中只保留一份副本，从而节省物理内存并实现进程间数据共享`▶ 1:26:21`。

### 内存堆方法

**堆（heap）**适合处理大量的小型内存申请。它是进程保留地址空间中由一个或多个页组成的区域，堆管理器可以把这部分区域进一步划分为更小的内存块并进行分配。

堆管理器是 Windows 执行体中负责分配和回收可变大小内存的一组函数。

#### 进程缺省堆

- 进程启动时会带有一个**缺省进程堆**；
- 该堆通常大小为 **1 MB**；
- 线程若要从缺省堆中分配内存，需要先调用 `GetProcessHeap` 获得指向该堆的句柄；
- 获得句柄后，可以调用：
  - `HeapAlloc`：从堆中分配内存块；
  - `HeapFree`：回收堆中的内存块。

#### 私有堆

进程也可以创建额外的私有堆：

- 使用 `HeapCreate` 创建一个新的私有堆；
- 使用 `HeapAlloc`、`HeapFree` 在该堆中分配和释放内存；
- 当进程不再需要该私有堆时，调用 `HeapDestroy` 释放其占用的虚拟地址空间。

### 内存映射文件与堆的适用场景对比

| 方式 | 适用场景 | 主要特点 |
|---|---|---|
| 区域对象 / 内存映射文件 | 大文件访问、跨进程共享内存 | 文件映射到虚拟地址空间，按内存数组访问，依靠缺页中断自动调入页面 |
| 内存堆 | 大量小型、可变大小内存申请 | 由堆管理器把页划分为更小的块，分配回收灵活，适合普通动态内存管理 |

## 9. 物理内存管理与页框状态转换

> 课件 第 118–124 页 · 讲解从 `1:28:20` 开始

### 物理内存管理：基本思想与清除策略

物理内存的管理首先涉及物理内存的划分方式，主要有两种场景`▶ 1:28:20`：

- **等长划分**：即页式内存管理中的页框，大小固定；最简单的管理方式是位图（BitMap），用一个二进制位标识对应页框是否已分配，但实际系统会采用更复杂的结构`▶ 1:28:20`。
- **不等长划分**：即可变分区，按需动态切分大小，类似菜市场按需求切肉`▶ 1:28:20`。

此外，内存堆分配采用"批发大块内存、零售小块给用户"的策略`▶ 1:28:20`。

在分页系统中，**清除策略（页框回收策略）**的要点如下：

- 分页系统工作的最佳状态是：发生缺页异常时，系统中有大量的空闲页框可供使用。
- 因此，**保存一定数目的空闲页框供给，比使用全部内存、在需要时才搜索一个页框有更好的性能**。
- 系统会维持一个空闲页框缓冲池：当需要使用一个已被置换出去的页框时，如果该页框还没有被新内容覆盖，只需将它从空闲页框缓冲池中移出，即可恢复该页面，避免重新从磁盘读入。

### 页框号数据库（PFN 数据库）

Windows 通过**页框号数据库（Page Frame Number Database，PFN 数据库）**管理物理内存：

- 数据库以**大数组**形式实现，每个数组元素对应一个物理页框，存储该页框的全部管理信息`▶ 1:28:20`。
- 每个元素是一个 `MMPFN` 结构，大小约 **24 字节**（随系统版本迭代可能增大）`▶ 1:28:20`。
- 全局变量 **`MmPfnDatabase`** 保存该数据库（数组）的首地址，以便系统随时访问`▶ 1:28:20`。
- 每个结构元素中附带链表指针，可将处于同一状态的页框串联成链表；PFN 数据库与进程页表之间存在对应关系`▶ 1:35:02`。

### 页框的七种状态

Windows 中页框共有 **7 种核心状态**，可分为两大类：常规状态与为支持清除策略而设的状态`▶ 1:28:20 · 1:32:55`。

| 状态 | 含义 | 对应 PTE 情况 / 后续处理 |
| --- | --- | --- |
| **活动/有效（Active/Valid）** | 该页框在某个进程的工作集中，是最常规的状态 | 对应页表项有效，从 PTE 高 20 位可获得页框号 PFN |
| **过渡（Transition）** | 系统正在从文件将内容读入该页框，或正在向文件写出该页框内容；I/O 操作未完成前不得分配给其他进程`▶ 1:28:20` | —— |
| **空闲（Free）** | 页框中的内容不再被需要，未分配，可随时分配给其他进程`▶ 1:28:20` | —— |
| **零初始化（Zeroed）** | 页框空闲且内容已被清零，用于需要全零页的场景（如栈空间）`▶ 1:28:20` | —— |
| **坏（Bad）** | 页框存在硬件错误（如同时出现读写校验错误），不能使用，被归入专用的坏页框链表`▶ 1:28:20 · 1:32:35` | —— |
| **修改（Modified）** | 曾在某进程工作集中，内容在使用期间**被修改过**，现已被移出工作集 | 见下文 |
| **后备（Standby）** | 曾在某进程工作集中，内容在使用期间**未被修改**，现已被移出工作集 | 见下文 |

#### 修改（Modified）状态

- 该页框曾在某个进程的工作集中，且内容在被该进程使用期间发生过改变。
- 它现在虽已被移出工作集，但页框中仍是该进程的内容：对应 PTE 的高 20 位仍然保存该页框号，只是该 PTE 被标记为 **invalid 和 transition**。
- 当进程再次访问该页时，**只需重新设定 PTE 标志并使其变为有效**，即可把页框从 modified 状态变回 active(valid) 状态，从而避免磁盘 I/O。
- 在该页框被系统用作其他用途之前，**必须先将其内容写入硬盘上的页文件**。

#### 后备（Standby）状态

- 该页框曾在某个进程的工作集中，但内容在使用期间**没有改变**。
- 与 modified 状态类似，它被移出工作集后，对应 PTE 高 20 位仍是该页框号，PTE 被标记为 **invalid 和 transition**。
- 当进程再次访问时，只需重新设置 PTE 标志、使其有效，页框即从 standby 状态变回 active(valid) 状态。
- 由于内容未修改，**回收或重新使用时无需写回磁盘**。

> **老师强调（置换处理流程）**：当页框被置换算法选中、从工作集取出时——若内容未被修改，可直接作为可分配页框回收，无需额外操作；若内容已被修改，32 位下 PTE 高 20 位仍保留原页框号，同时将 PTE 标记为 invalid（有效位为 0），用两个位标记其置换状态。进程再次访问时，将对应 PTE 的标记改为 `01` 即可触发缺页处理；修改过的页框需先写回磁盘，未修改的直接复用。页框一旦被正式分配出去，就不再回到回收流程`▶ 1:33:22`。

设置 modified 与 standby 这两种状态，本质上是为了区分被置换页框的内容**是否被修改**，以支持页清除策略`▶ 1:32:55`。

### 页框数据库的整体组织与状态转换

PFN 数据库为结构数组，数组元素通过链表指针把相同状态的页框组织成多条链表，并由统一的**链表头**管理；这些链表与进程页表相对应`▶ 1:35:02`。课件示意图展示了各链表、线程与状态转换之间的关系：

- 涉及的链表包括：**后备页面链表、修改页面链表、空闲页面链表、零初始化页面链表、坏页面链表**，以及进程的**工作集**。
- 主要转换与参与的系统组件：

| 转换 / 动作 | 说明 |
| --- | --- |
| 工作集 → 后备/修改链表 | 由**置换**操作触发，按页面是否被修改分别进入两条链表 |
| 后备页面 → 工作集 | 发生 **"软"缺页异常**时，页面仍在物理内存中，直接恢复 PTE 即可 |
| 从磁盘读入页面 → 工作集 | 页面不在内存时，从磁盘读入（经过过渡状态） |
| 需求零缺页异常 | 请求一个全零页面时，从零初始化页面链表获取页框 |
| 修改页面链表 → 磁盘 | 由**已修改页面写出线程**负责将脏页写回页文件 |
| 零初始化页面链表 | 由专门的**零初始化页面线程**把空闲页框清零后挂入 |

## 10. 写时复制机制

> 课件 第 125 页 · 讲解从 `1:44:07` 开始

### 写时复制机制（Copy on Write, COW）

写时复制技术基于**内存共享**实现，其核心思想是：让多个进程先以只读方式共享同一物理内存页面，只有当某个进程真正需要修改页面内容时，才为该进程复制出一份私有副本，从而推迟甚至避免不必要的页面复制，节省物理内存并提高效率。

#### 两类共享模式

| 共享模式 | 特点 |
|---|---|
| 公共共享（无约束共享） | 进程之间不受限制地共享内存 |
| 私有共享（private，受限共享） | 多个进程可以共享同一个物理页面，但**只允许读操作**；一旦有进程执行写操作，就触发写时复制机制`▶ 1:44:07` |

#### 工作过程

以课件图示为例，两个进程共享三个物理页面，每个页面都被标记为"写时复制"：

1. **初始共享阶段**：两个进程的地址空间都映射到相同的物理页面（原始数据），这些页面以只读方式共享。
2. **触发写操作**：当其中一个进程试图修改某个页面（如图中的页面 2）的数据时，触发写时复制机制。
3. **复制页面**：系统为执行写操作的进程分配一个新的物理页面，并将原页面 2 的内容复制到新页面中。
4. **调整映射关系**：写时复制**按页**调整映射——执行写操作的进程，其地址空间中页面 2 改为映射到新复制的页面；其余未被写入的页面仍然保持共享状态`▶ 1:44:07`。
5. **结果**：新复制的页面对执行写操作的进程是**私有**的，其他共享该写时复制页面的进程看不到这个新页面，仍然访问原始页面。

> **关键点**：写时复制的映射调整粒度是"页"，只有发生写操作的那一页会被复制并私有化，同一进程中其他未写的页面继续与别的进程共享`▶ 1:44:07`。

#### 示意图文字说明

- **写操作前**：两个进程的地址空间共同指向物理内存中的同一份"原始数据"，三个共享页均标志为写时复制。
- **某进程写页面 2 后**：产生"页面 2 的复制"，该进程的页面 2 映射到新副本，另一进程的页面 2 以及双方其余页面仍指向原始物理页面。

这种机制使得进程间可以在保证数据私有性和隔离性的前提下，最大限度地共享物理内存：读时共享、写时才分离。

## 11. 虚拟内存核心概念回顾与总结

> 课件 第 126 页 · 讲解从 `1:45:26` 开始

### 虚拟内存核心机制

虚拟内存的核心逻辑是：每个进程拥有独立的虚拟地址空间，它是对物理内存的抽象，虚拟地址到物理地址之间通过地址映射完成转换`▶ 1:45:26`。这一机制由硬件与内核软件协同完成：

- **硬件层**：MMU 负责地址转换，并在异常情况下触发硬件异常`▶ 1:45:50`。
- **内核软件层**：负责页表、页表项等数据结构的管理`▶ 1:45:50`。
- **数据存储层**：分为内存和磁盘两级存储`▶ 1:45:50`。

虚拟内存的本质是**把内存作为磁盘的缓存**；该机制同时简化了内存管理，并通过进程私有空间的隔离性，保证一个进程的地址空间不会被其他进程破坏`▶ 1:47:04`。

### 基本概念

- **虚拟内存、虚拟地址、虚拟地址空间**
  - 每个进程的虚拟地址空间具备三个特性：统一布局、巨大尺寸、进程私有且互不可访问；布局位置还可进行随机化处理`▶ 1:46:40`。
- **页表表项、多级页表、反转页表（倒排页表）**
  - 页表及页表项由内核管理，是地址转换所依赖的数据结构`▶ 1:45:50`。
- **快表 TLB**
  - 用于缓存常用页表项，加速地址转换`▶ 1:47:39`。

### 地址转换与缺页处理

- 虚拟地址由**页号 + 页内偏移**组成，MMU 负责将虚拟地址转换为物理地址`▶ 1:47:39`。
- 转换流程：
  1. 先查 TLB，命中则直接得到地址；
  2. TLB 未命中时查询页表；
  3. 若页表项显示页面不在内存，或访问违反权限约定，则触发 **Page Fault（缺页异常）**`▶ 1:47:39`。
- TLB、页表、Cache 都存在"命中 / 未命中"的判断逻辑`▶ 1:47:39`。
- 发生缺页时由操作系统介入：分配页框并将页面读入；现代系统通过**提前准备页缓冲**来解决页框不足的问题`▶ 1:47:39`。

### 虚拟内存管理

- **取页策略**：按需取页、预取页。
- **驻留集管理**：固定驻留集、可变驻留集。
- **置换范围与策略**：局部置换、全局置换。
- **清除策略**：页缓冲。
- **加载控制**：调控内存中并发进程的数量（度）。
- 其他机制：**内存映射文件**、**写时复制（Copy-on-Write）**。

### 虚拟内存管理的三个目标

1. **对用户透明**：用户无需感知地址转换过程`▶ 1:49:05`。
2. **借助硬件支持提升效率**：如 MMU、TLB`▶ 1:49:05`。
3. **通过统一地址空间实现保护**：进程间地址空间隔离互访`▶ 1:49:05`。

> **老师强调**：本章核心结论——虚拟内存本质上是把内存当作磁盘的缓存，同时兼具简化内存管理和进程隔离保护的作用`▶ 1:47:04`；TLB、页表、Cache 三者都要掌握"命中/未命中"的判断逻辑`▶ 1:47:39`。
