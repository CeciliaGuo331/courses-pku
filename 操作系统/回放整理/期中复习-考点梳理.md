### 老师反复给的答题方法（本身就是"考点"）

1. **核心 20%**："中断异常机制 + 调度时机"这两块，加上虚拟存储，就是全课最核心的 20%，其余 80% 可以推出来 `[w4-2 49:44]`。
2. **无从下手时，从数据结构切入**：每个模块都有依赖的数据结构——中断异常 → 中断向量表 + 系统调用表；进程 → PCB；地址空间 → `mm_struct` / VMA；调度 → 就绪队列 + PCB 里的调度字段 `[w3-2 1:14:57]` `[w1-1 1:27:47]`。
3. **先明确场景，再给结论**：架构（x86 / RISC-V）、OS（Linux / Windows / xv6）、位宽不同，答案不同。例：问"虚拟地址空间多大"，要先说是 x86-64 四级页表（48 位）还是 RISC-V Sv39（39 位）`[w1-1 16:49]`。
4. **硬件先、软件后，不交错**：任何事件处理都是"硬件完成响应 → 交给软件处理 → 进调度 → 返回用户态"，"以往考试很少有同学能答对这个顺序" `[w4-2 51:21]`。
5. **机制与策略分离**：几乎每个分析题都能用上（中断机制 vs 中断向量表内容；"按优先级选进程" vs "怎么调优先级"）`[w3-1 1:39:19]`。
6. **调度算法不要背优缺点，要像提方案一样多维度分析**：公平性、饥饿、对 I/O 型 / CPU 型 / 长 / 短进程是否友好、开销、响应时间、吞吐量 `[w4-2 22:38]` `[w6-1 1:31:46]`。

## 一、全课主线：一次 `read()` 的完整生命周期

老师说"已经重复讲了六七次，必须牢记先后顺序" `[w3-1 1:36:46]`。下面这条时间线串起了第 2、3、4 章几乎所有高频考点，**能默写出来，流程题基本就稳了**。

```
进程 A（用户态）执行 read(fd, buf, n)
 │ ① 库函数把 系统调用号→a7/eax，参数→寄存器，执行陷入指令（RISC-V ecall / x86 int 0x80）
 ▼ ── 硬件 ──────────────────────────────────────────────
 │ ② 硬件：用户态→内核态；保存少量关键现场（PC/状态/栈指针等）；
 │        按中断号查【中断向量表】→ 跳到系统调用总入口         ← 硬件到此为止
 ▼ ── 软件（内核） ──────────────────────────────────────
 │ ③ 汇编入口：保存其余寄存器（SAVE_ALL / xv6 trapframe）
 │ ④ 用系统调用号查【系统调用表】→ sys_read          ← 第二张表！
 │ ⑤ 启动 I/O（交给 DMA/设备控制器），A：运行态 → 阻塞态，进等待队列
 │ ⑥ 调度：选 B 上 CPU（上下文切换，换页表）           ← 阶段一结束
 ⋮   …… B 在运行 ……
 │ ⑦ 设备完成 → 发【中断】（异步）→ 硬件响应 → 中断处理程序
 │ ⑧ 内核发现 A 等的数据到了：A 阻塞态 → 就绪态（不能直接到运行态）
 │ ⑨ 中断处理完 → 进调度：若 A 优先级更高（可抢占）→ 置 need_resched → 切到 A
 │ ⑩ A 返回用户态前最后一刻：检查 sigpending，处理所有待处理信号
 │ ⑪ RESTORE_ALL，回到用户态 ecall/int 的【下一条】指令       ← 阶段二结束
 ▼
进程 A 继续执行
```

这一条线上对应的考点：
- ②③ 软硬件交接点 → 第二节 2.2
- ②④ 两张表 → 第二节 2.4
- ⑤⑥ + ⑦⑧ = read/write **两个阶段**（只写一个阶段丢分）→ 第二节 2.4
- ⑤⑧ 状态转换规则 → 第三节 3.2
- ⑥⑨ 调度时机、可抢占 → 第四节 4.1
- ⑩ 信号处理时机 → 第二节 2.4
- ⑪ 返回地址 → 第二节 2.2

## 二、第 0~2 章：OS 概述、运行环境与运行机制

### 2.1 第 0~1 章（导论、概述）—— 分值不大，以概念题为主

**考点**
- ★★ OS 的定义：**以尽量有效、合理的方式组织和管理计算机软硬件资源**（"必须牢记"）`[w2-1 06:47]`；三个角色：资源管理者 / 服务提供者（系统调用）/ 机器扩展（虚拟机思想源头）。
- ★★ 三种观点：资源管理观点、进程观点、虚机器（分层）观点 `[w2-1 13:24~21:41]`。
- ★ 三类资源的抽象：**CPU → 进程，内存 → 地址空间，外设/磁盘 → 文件** `[w3-2 07:52]`。
- ★★ 多道程序设计的目的（提升 CPU 与 I/O 并行、资源利用率），以及它"催生了调度"`[w2-1 35:33]`。
- ★★ **SPOOLing（假脱机）**：用软件代替卫星机；输入井/输出井作为缓冲；拆成输入进程、调度进程、作业控制进程、输出进程，两两是**生产者-消费者**关系；今天的打印守护进程就是它 `[w2-1 43:13~47:24]`。
- ★ hello world 的执行全流程（shell → 文件系统找 ELF、查魔数 → 建进程/PCB → **进调度**（课件红色问号处）→ 第一条指令触发**缺页** → 回到**该条指令重新执行** → write 系统调用 → exit）`[w1-2 28:13]`。哪些步骤在用户态、哪些在内核态。
- ★ 静态 vs 动态资源分配（动态利用率高，但带来死锁）`[w2-1 18:12]`。

**易错点**
- 程序执行的第一条指令**不是** `main` 里的代码（前面有 `_start` 等启动代码）`[w1-2 16:44]`。
- 创建进程后**不会直接执行**，要先经过调度 `[w1-2 28:13]`。
- 触发缺页的那一刻进程还在**用户态**，处理才进入内核态 `[w1-2 30:45]`。
- 内核**不是进程**；用户态运行的不一定只有用户进程，也有系统进程（守护进程）`[w1-1 1:14:44]`。

**启动流程（xv6 / RISC-V，开卷可查，但要理清"接力"逻辑）**
- 固件（OpenSBI，M 态）→ 跳到内核入口 → 每核建 16KB 启动栈 → `main` 初始化 → 第一个用户进程（`userinit`，**不是 fork 出来的**）→ 每核进入永不返回的 `scheduler` 循环 `[w1-2 1:42:32~1:45:30]`。
- 注意版本差异：课上读的是**上游 xv6-riscv**（有 `start.c`，从 M 态起步、`mret` 进 S 态）；实验用的 xv6-k210 由 RustSBI 引导，**直接进 S 态，没有 `start.c`** → 笔记 0.6、2.7。

### 2.2 中断与异常机制 ★★★（全课第一重点）

老师原话："应用程序如何与操作系统交互、如何理解'操作系统由中断/异常事件驱动'、中断与异常的来源差异及处理方式的异同——**年年考察**，要求真正理解" `[w2-1 1:04:32]`。

**考点**
- ★★★ 中断 vs 异常：

  | | 中断 | 异常 |
  |---|---|---|
  | 来源 | CPU **外部**（I/O 设备、时钟、硬件故障） | CPU **执行指令本身**（系统调用、缺页、除零、断点…） |
  | 同步性 | **异步**，可延后处理 | **同步**，必须立即处理 |
  | 返回地址 | 总是**下一条**指令 | 看类型：陷入（系统调用）→ 下一条；故障（缺页）→ **重新执行本条**；终止 → 不返回 |

  与 ICS 的关系：ICS 把所有事件都叫"异常"（中断/陷阱/故障/终止），本课程拆成中断 + 异常两类，**覆盖的事件相同，只是叫法不同** `[w3-1 07:11]`。
- ★★★ "OS 是中断/异常驱动的"：没有事件时 OS 空闲；中断机制是"飞机的引擎"`[w2-1 1:39:17]`。中断异常机制的三大作用：响应外设、捕获系统调用、捕获非法操作（如写只读页）`[w2-1 1:42:11]`。
- ★★★ **软硬件分工**：硬件负责"捕获 → 保存少量现场 → 查中断向量表 → 改 PC"，之后才交给 OS；OS 保存其余寄存器、识别原因、处理、返回 `[w3-1 12:25]` `[w3-1 22:31]`。"考试常有同学理不清软硬件交接"。
- ★★ 中断向量表：OS **引导初始化时**建好，是软硬件协同的接口；硬件只负责查表跳转 `[w3-1 17:25]`。
- ★★ 特权级与特权指令：用户态只能执行非特权指令。课堂派题答案：**启动 I/O、内存清零、修改程序状态字、设置时钟 → 特权指令**；**访管指令（ecall / int 0x80）→ 非特权指令** `[w2-1 1:32:18~1:33:57]`。
- ★★ 态转换的唯一途径：用户态 → 内核态**只能**经中断/异常/陷入；内核态 → 用户态靠**设置程序状态字**（x86 `iret`，RISC-V `sret`）`[w2-1 1:34:24]`。
- ★ RISC-V 三种模式 U/S/M；x86 四个特权环只用 R0/R3；x86 每个特权级有独立栈指针（TSS 里的 SS0/ESP0…），切换时硬件自动换栈 `[w2-1 1:22:20]`。
- ★ Linux 中断处理的**上半部/下半部**：上半部紧急、关中断、快速完成；下半部开中断、延后处理（战地医院比喻）`[w3-1 25:59]`（联系计网的 NAPI → 笔记 2.2）。
- ★ x86 中断门 vs 陷阱门：中断门进入时**自动关中断**，陷阱门不关；Linux 系统调用（0x80）用**陷阱门**、DPL=3 `[w3-1 35:51]` `[w3-1 1:14:45]`。

**易错点**
- 访管指令**是非特权指令**（名字像"管理"，但必须让用户态能执行，否则没法进内核）。
- 硬件**只保存少数关键寄存器**，其余寄存器是软件保存的 `[w3-1 22:31]`。
- 中断处理完**不是**直接返回原程序，而是**先进调度** `[w2-1 1:48:02]`。
- 架构差异：x86 陷入时硬件自动换到内核栈（读 TSS）；**RISC-V 硬件不自动换栈**，只把 PC 存进 `sepc`、原因写进 `scause`、跳到 `stvec`，换栈和保存寄存器全由软件（xv6 的 `trampoline.S` / `uservec`）完成 → 笔记 2.7。

**难点**
- x86 保护模式下 IDT → 门描述符 → 段选择符 → GDT → 段基址 + 偏移 的寻址链（老师说了解即可，开卷可查）。
- 把"中断异常机制"和后面的"进程状态转换""调度时机"对应起来：**每一次状态转换背后都是一次中断/异常处理** `[w3-2 47:30]`。

### 2.3 机制与策略分离 ★★

- 定义：机制是固定不变的底层实现，策略是可调整的上层决策 `[w3-1 1:39:19]`。
- 课上给的三个例子（分析题可直接套）：
  1. 中断异常机制 = 机制；中断向量表、系统调用表里填什么 = 策略 `[w3-1 1:41:35]`；
  2. 硬件中断优先级固定 = 机制；通过屏蔽/开放改变响应顺序 = 策略 `[w3-1 1:40:30]`；
  3. "按优先级选进程" = 机制；改优先级（优先级继承、Windows 动态提升）= 策略 `[w3-1 1:43:02]` `[w6-1 1:20:46]`。
- 系统调用本身就是"机制与策略分离的典型实例"：进内核的通路固定，进去后干什么可变 `[w3-1 1:04:57]`。

### 2.4 系统调用 ★★★

**考点**
- ★★★ **中断向量表与系统调用表是两张不同的表**：中断向量表里只有"系统调用入口"一项；进内核后再用系统调用号查系统调用表找到 `sys_xxx`。"往年 30%~40% 的学生误以为是同一张表" `[w3-1 52:56]`。
- ★★★ **read/write 的两个阶段**（见第一节时间线 ⑤⑥ 和 ⑦⑧）："往年常考，只写一个阶段丢分" `[w3-1 1:17:04]`。
- ★★ 系统调用 vs 过程调用（"常见面试题/经典考题"`[w3-1 47:23]`）：陷入指令 vs `call`；切换特权级 vs 不切换；用独立的内核栈 vs 同一用户栈；入口由系统调用号间接决定 vs 地址直接给出；返回前可能被调度、要处理信号 vs 直接返回；开销大得多。
- ★★ 系统调用实现的**静态准备**（封装成库、陷入指令、编译器支持、初始化建表、定好编号与传参方式）+ **动态执行**（陷入 → 总入口 → 保存现场 → 查表分派 → 执行 → 返回）`[w3-1 1:35:06]`。
- ★★ 参数传递三种方式：绑在指令里（已不用）/ 寄存器（主流）/ 放内存，传指针 `[w3-1 1:05:22]`。
- ★★ 返回路径：关中断 → 查 `need_resched`（非 0 就去调度，不回来）→ 查 `sigpending` → `RESTORE_ALL` `[w3-1 1:28:02~1:33:18]`。
- ★ 库函数与系统调用的关系：`fopen` 封装 `open`、`printf` 最终调 `write`；用 `strace` 观察 `[w3-1 45:02]`。命令行命令**不是**系统调用 `[w3-1 44:12]`。

**易错点**
- 信号用**位向量**记录，**同类信号不排队**：第一个没处理时第二个直接丢 `[w3-1 12:02]`。
- 信号在"内核态**返回用户态前的最后时刻**"统一处理，而且一次全部处理完 `[w3-1 1:33:18]`（ICS 第 8 章的内容，要能接上）。
- 栈布局顺序：先硬件压 SS/ESP/EFLAGS/CS/EIP → 再软件压系统调用号 → 再 SAVE_ALL `[w3-1 1:23:06]`。
- 系统调用"是用户态进入内核态的唯一接口"这句话要按课件语境理解：它是**用户程序主动**请求内核服务的唯一接口；用户态进内核的途径还有中断和其他异常。

## 三、第 3 章：进程线程模型

### 3.1 进程概念与 PCB ★★

**考点**
- ★★ 进程定义（课件标色部分）："具有独立功能的程序**关于某个数据集合的一次运行活动**，是系统进行**资源分配和调度**的独立单位" `[w3-2 33:01]`。要能解释"一次"（同一程序跑两次 = 两个进程）和"数据集合"。
- ★★ 引入线程后：进程 = 资源分配单位，线程 = 调度单位；**只有进程和线程同时存在时**才有这种分工 `[w4-1 1:11:32]`。
- ★ 并发环境的特点：结果不可再现、执行间断、资源共享、相互制约；对比顺序执行的**封闭性** `[w3-2 21:51~28:02]`。
- ★★ PCB：进程存在的**唯一标志**，与进程一一对应；进程表在内存中**预先分配** `[w3-2 1:16:03~1:19:01]`。Linux `task_struct`，xv6 `struct proc`，Windows 拆成 EPROCESS/KPROCESS/PEB。
- ★★ PCB 中的三个重点（"课件三个核心重点"）：
  1. 可执行文件的位置（能通过 inode 找到磁盘文件）；
  2. **地址空间**（`mm` 指针）；
  3. **打开文件表**（子进程继承父进程的；默认 0/1/2）`[w3-2 1:26:55~1:30:18]`；
  4. 以及**上下文**：PC、PSW、栈指针、**页表指针**最重要 `[w3-2 1:23:15]`。
- ★ 进程分类：用户进程 / 系统进程（守护进程，平时睡眠，有任务才唤醒）；CPU 密集型 / I/O 密集型；Unix 有进程家族树（1 号进程为根），Windows 没有 `[w3-2 36:31~40:16]`。

### 3.2 进程状态模型 ★★★

**考点**
- ★★★ 三状态：运行 / 就绪 / 阻塞（等待、睡眠）。6 种可能转换只保留 4 种：
  - **没有 阻塞 → 运行**（事件发生后必须先进就绪队列排队，保证调度确定性）；
  - **没有 就绪 → 阻塞** `[w3-2 44:02]`。
- ★★★ 每种转换的**触发事件**要能举例：就绪→运行（被调度选中）、运行→就绪（**时间片到** / 被抢占）、运行→阻塞（`wait`、慢速 I/O 系统调用）、阻塞→就绪（I/O 完成中断、子进程结束）`[w3-2 45:58~47:30]`。
- ★★ 五状态（+ 创建态、终止态）是**最接近实际系统**的模型；七状态（+ 就绪挂起、阻塞挂起）现在很少用 `[w4-1 16:11]`。
  - 创建态的意义：负载过重时的缓冲（故宫预约比喻），**不是所有系统都有**；终止态（善后、回收）**主流系统都有** `[w3-2 52:07~54:17]`。
- ★★ 实际系统的状态名对应：
  - Linux：`TASK_RUNNING` **同时包含就绪和运行**；睡眠分可中断 / 不可中断；还有 `ZOMBIE`、`STOPPED`（给 ptrace 调试用）`[w3-2 1:10:21]`；
  - xv6：`RUNNABLE`(就绪) / `RUNNING` / `SLEEPING`(阻塞) / `ZOMBIE`；外加 `UNUSED`/`USED` 表示 PCB 槽位状态（不算常规进程状态）`[w3-2 1:13:00]`。

**易错点**
- 用户级线程的情况：线程执行阻塞系统调用，内核把**整个进程**阻塞，但线程库里这个线程的状态**仍显示为 running**（实际没在运行）`[w4-1 1:21:05]` `[w4-1 1:43:31]`。

### 3.3 地址空间 ★★

**考点**
- ★★★ OS 提供给进程的是**虚拟地址空间**，不是物理地址空间（"很多学生容易混淆，需明确记住"）`[w3-2 15:10]`。
- ★★ 虚拟地址空间四个特点：**巨大、布局统一、安全、稀疏** `[w3-2 1:36:31]`。大小要能按场景说出：x86-64 Linux 48 位（4 级页表，4×9+12）；RISC-V Sv39 为 39 位（xv6 的 `MAXVA` 实际只用到 2^38）。
- ★★ 稀疏 → 不能用大数组，只为有内容的区域建结构：每个区域一个 **VMA（`vm_area_struct`）**，记起止地址、权限、flags；组织成**链表或平衡树**（AVL / 红黑树，不同系统/版本不同），树的好处是 `mmap` 时快速查重叠 `[w3-2 1:46:30~1:53:45]`。
- ★★ `task_struct → mm_struct → VMA 链表/树`；`mm_struct` 里还有**顶级页表指针**，运行时装进 CPU 寄存器（x86 CR3 / RISC-V `satp`）`[w3-2 1:54:34]`。
- ★ 实验现象解释：两个进程打印同一变量的**虚拟地址相同**（各自独立的地址空间、同一可执行文件布局），物理地址不同；现代系统地址不同是因为 **ASLR** `[w3-2 1:39:00]` `[w3-2 1:55:44]`。
- ★ 创建进程时**不真正读入**代码和数据，只建立 VMA 映射；堆、栈运行时动态生成 `[w3-2 1:43:32]`（与 hello world 第一条指令缺页呼应）。

### 3.4 进程控制与 fork ★★★

**考点**
- ★★ 进程控制操作（创建、撤销、阻塞、唤醒）都是**原语**：不可分割、不可中断；最基本的实现方法是**关中断/开中断** `[w4-1 18:43~20:54]`。
- ★★★ 创建进程必须做的三件事：**分配 PID、分配 PCB、分配地址空间**，然后初始化 PCB、挂入就绪队列 `[w4-1 23:18]`。
- ★★ Unix 的 `fork + exec` 设计（"small is beautiful"）：`fork` 复制出几乎一样的子进程，`exec` 换掉代码和数据 `[w4-1 24:59]`。xv6 源码阅读题：shell 用 `fork/exec/wait` 的好处（可以在 fork 和 exec 之间做 I/O 重定向）→ 笔记 3.6。
- ★★★ **写时复制（COW）**：fork 时复制 `task_struct`/`mm_struct`/VMA，但**不复制物理页**；父子页表都指向相同物理页并标为**只读** + COW；任何一方写入 → **页错误异常** → 内核复制该页、改映射 → 继续写 `[w4-1 33:28~38:33]`。

**易错点**
- ★★★ **COW 不是 Linux 发明的**，是存储管理里早已有的技术，Linux 只是拿来优化 fork（"往年 40%~50% 的考生答错"）`[w4-1 28:42]`。
- 课上说"执行 exec 时触发写保护异常"——更准确的说法：**任何写操作**都会触发 COW 页错误；而 `exec` 是直接丢弃旧映射、为新程序建新映射，这样子进程就不必复制父进程的页了，这才是 COW 省下来的开销。
- xv6-riscv 上游的 `fork` 是**真复制**（`uvmcopy` 逐页拷贝），没有 COW（COW 是 MIT 6.S081 的一个 lab）→ 不要说"xv6 用了 COW"。

### 3.5 线程模型 ★★★

**考点**
- ★★ 为什么引入线程：应用需要（Word 的输入/排版/保存线程；**多线程 Web Server**：dispatcher + worker 线程池）、开销小、性能好 `[w4-1 44:13~59:56]`。
- ★★ 没有线程时 Web Server 的另外两种方案：单进程顺序处理（慢）、**I/O 多路复用 / 有限状态机**（`select`，快但难编程）；三种方案的本质区别在于系统调用是否阻塞 `[w4-1 1:05:09~1:08:39]`（联系计网：C10K、epoll）。
- ★★ 线程私有 vs 共享：私有的有**状态、上下文（寄存器）、栈和栈指针**；共享的有地址空间、打开文件等；线程栈之间**没有内存保护** `[w4-1 1:13:09~1:15:27]`。
- ★★★ 线程的三种实现（"考试常考"）`[w4-1 1:16:12]`：

  | | 用户级线程 | 内核级线程 | 混合 |
  |---|---|---|---|
  | 谁管理 | 用户态线程库（运行时） | 内核 | 两者，经 LWP 连接 |
  | 内核是否感知线程 | 否，只知道进程 | 是 | 是（感知 LWP） |
  | 一个线程阻塞 | **整个进程阻塞** | 只阻塞该线程 | 只阻塞对应 LWP |
  | 能否多核并行 | **不能**（"要能推导该结论"） | 能 | 能 |
  | 切换开销 | 小（不进内核） | 大 | 介于中间 |
  | 典型 | 早期 Pthreads 实现 | Windows、今天的 Linux | Solaris（8 之前多对多） |

- ★★ 用户级线程阻塞问题的两种补救：换成非阻塞系统调用 / 重写 I/O 库（加"马甲"：将要阻塞前先 `yield`）`[w4-1 1:27:38]`。
- ★ 协程：与 OS 无关，由语言/库实现，比线程更轻；C10K 问题 `[w4-1 1:35:05~1:38:17]`。
- ★★ **可再入（reentrant）**："需要复习"：纯代码、执行中不修改自身、状态放栈上；`rand()` 这种依赖静态状态的函数不可再入 `[w4-1 1:40:18]`。

**易错点**
- 课上说"Linux 采用用户级线程方案"（`[w4-1 1:26:15]`），这里要辨析：**Pthreads 只是一套 API 标准**，可以用用户级实现，也可以用内核级实现；**今天 Linux 的 NPTL 是一对一内核级线程**（`pthread_create` → `clone`）。答题时可以写"Pthreads 是 POSIX 线程接口，早期多为用户级实现"，避开这个坑 → 笔记 3.4。
- "只有线程、没有进程"的系统中，线程就等同于传统进程，谈不上"进程是资源单位、线程是调度单位"。

## 四、第 4 章：进程线程调度

### 4.1 调度基本概念 ★★★

**考点**
- ★★★ 调度三问题：**What**（算法）、**When**（时机）、**How**（上下文切换）`[w4-2 41:07]`。
- ★★★ **调度时机**（"待会要提问，要认真记"，"核心 20%"）`[w4-2 41:54~53:30]`：
  - 按事件列：进程正常终止、出错终止、创建新进程、运行进程阻塞（等 I/O / 等资源）、**阻塞进程变就绪**（I/O 中断）、时间片到、主动让出（`yield`）；
  - 本质：**就绪队列发生变化**或 CPU 空闲时；
  - 统一说法：**中断/异常/系统调用处理完、返回用户态之前的最后时刻**。
- ★★ 两种视角对应：进程状态模型的每条边 ↔ 中断异常机制里的一个确定事件（fork → 系统调用；时间片到 → 时钟中断；唤醒 → I/O 中断）`[w4-2 45:37]`。
- ★★ **时钟中断 ≠ 时间片**：时钟中断是硬件按固定频率发出的信号；时间片是内存里的计数器，每次时钟中断减 1，减到 0 才"时间片到" `[w4-2 46:59]`。
- ★★ 调度层次：长程（创建 → 就绪，控制负载）、中程（挂起/激活，内外存交换）、**短程**（就绪 → 运行，毫秒/微秒级，"快是核心要求"）`[w4-2 28:41~31:21]`。
- ★★ 上下文切换：先看 `need_resched` 要不要换；不换就直接弹栈恢复原进程；换才保存旧进程寄存器到 PCB、恢复新进程，**重点是换页表基址寄存器** `[w4-2 1:04:30~1:08:12]`（xv6 的 `swtch.S` → 笔记 4.1、4.10）。
- ★★ 切换开销：**直接**（保存/恢复寄存器、切地址空间的指令）+ **间接**（cache/TLB 失效后的 miss）；缓解：TLB 条目带进程标识（ASID）`[w4-2 1:12:53~1:14:41]`。
- ★ 没有就绪进程时运行 **idle 进程**，它能被任何事件打断 `[w4-2 33:31]`。
- ★ 不同系统的目标：批处理（吞吐量、周转时间、CPU 利用率）、交互式（响应时间、公平）、实时（截止时间）`[w4-2 1:15:13~1:17:47]`。
- ★ 调度依据必须**在 PCB 里有记录**（如 Windows 基本优先级 + 当前优先级两个字段）`[w4-2 1:23:47]`。

**易错点**
- "以往考试很少有同学能答对顺序"：硬件响应 → 软件处理事件 → 状态/队列变化 → 决定是否调度 → 返回用户态 `[w4-2 51:21]`。
- 优先级 ≠ 优先数：优先级是真实的轻重缓急，优先数是量化它的数字（要先说清"数越大优先级越高还是越低"）`[w4-2 1:27:23]`。
- Ctrl+C 和 `kill` 都是**内核**向目标进程发信号，区别只是进内核的路径（Ctrl+C 走键盘中断，`kill` 走系统调用）；这和"可抢占"无关 `[w4-2 1:50:35]`。

### 4.2 抢占与 I/O 型偏好 ★★★

- ★★★ 抢占式 vs 非抢占式（"核心概念"，抢占是可以跟其他规则组合的"前缀属性"）`[w4-2 26:30]`。
- ★★★ 课堂练习原题 `[w4-2 1:35:59]` `[w6-1 11:24]`：
  - "出现比当前运行进程优先级更高的就绪进程"的两类最常见情况：① 当前进程 `fork` 出高优先级子进程；② 高优先级进程等的 I/O 完成，从阻塞变就绪；
  - "当前进程因自身原因无法继续运行"：结束、出错、阻塞（等 I/O、`wait`）、主动让出。
  - 实现：内核处理完事件，在返回前比较优先级 → 置 `need_resched` → 调度。**不需要额外机制** `[w6-1 12:29]`。
- ★★ 为什么偏好 I/O 密集型进程（两条理由）`[w4-2 1:41:11]`：① 它很快发 I/O 让出 CPU，让 CPU 和外设同时忙，**整体资源利用率高**；② 它的时间片常用不完，优先调度它算是补偿。
- ★★ 时间片大小：太长 → 退化为 FCFS；太短 → 切换开销占比高；经验值 10ms 片 / 0.1ms 切换 ≈ 1% 开销 `[w6-1 38:48~40:12]`。

### 4.3 调度算法 ★★★（计算题 + 分析题）

**要会算的**
- FCFS / SJF / SRTF（抢占式 SJF）/ HRRN / RR 的**周转时间、平均周转时间、吞吐量**；课上例题：P1=24、P2=3、P3=3 按 FCFS 平均周转 (24+27+30)/3 = 27 `[w6-1 19:08]`。
- **响应比 = 1 + 等待时间 / 运行时间**（每次调度都要重算，所以开销大、少用）`[w6-1 30:20]`。
- 课堂派练习：A、B 两个 CPU 密集型 + C（I/O 密集型，1ms CPU + 10ms 磁盘）在不同算法下的 **CPU / 磁盘利用率** `[w6-1 48:06~54:38]`。结论：FCFS 和大时间片 RR 下磁盘几乎闲置；小时间片 RR 磁盘利用率可接近 90%，但切换多；SRTF 下 C 一直优先，B 可能饥饿。
- 实时：可调度性 `Σ Cᵢ/Pᵢ ≤ 1`；RM 的充分条件 `≤ n(2^(1/n) − 1)` → 笔记 4.7。

**要会分析的（对比维度：抢占?/饥饿?/偏好?/开销/适用场景）**

| 算法 | 抢占 | 饥饿 | 一句话要点 |
|---|---|---|---|
| FCFS | 否 | 否 | 简单公平；短作业等长作业；I/O 型吃亏 |
| SJF / SRTF | 否 / 是 | **是**（长作业） | 平均周转时间**最短**（同时到达时可用交换法证明）；要预知运行时间 |
| HRRN | 否 | 否 | FCFS 与 SJF 的折中；每次都要算响应比，开销大 |
| RR | 是 | 否 | 公平、响应快；**长度相近的进程用 RR 周转反而更差**（两个 100ms 进程：RR 分别 199/200 结束，FCFS 是 100/200）`[w6-1 41:35]` |
| 虚拟轮转 | 是 | 否 | 从 I/O 返回的进程进**辅助队列**优先调度，对 I/O 型更公平 `[w6-1 46:32]` |
| 最高优先级 | 可选 | **是** | 系统 > 用户、前台 > 后台、偏好 I/O 型；有**优先级反转** |
| 多级反馈队列 | 是 | **是**（CPU 型沉底） | 见下 |
| 彩票调度 | — | 概率上否 | 票多中签概率高；可以把票转给别人 |

- ★★★ **多级反馈队列**规则（"重点讲解"）`[w6-1 1:22:09~1:29:46]`：
  - 级别越低，优先级越低、**时间片越长**；高级队列空了才调度低级队列；同级内 RR；
  - 新进程进最高级；**用完时间片 → 降一级**（最底层不再降）；
  - **因阻塞放弃 CPU → 唤醒后回原级、不降级**（这就是对 I/O 型的偏好）；
  - 被抢占 → 回原级，通常放队首；
  - ★★★ **课件打问号的两处 = 考点**（"没有唯一标准答案，属于策略"）`[w6-1 1:25:56]`：① 解除阻塞后放回原队列的**队首还是队尾**？② 再次调度时用**剩余时间片、新时间片，还是奖励时间片**？答题要写出各选项和理由。

**优先级反转 ★★★**
- 定义：低优先级进程占着高优先级进程需要的资源，高优先级被阻塞，中优先级（不需要这个资源）反而一直在运行 `[w6-1 1:09:21]`。
- **只出现在基于优先级的抢占式调度中**，非抢占不会出现 `[w6-1 1:08:03]`。
- 案例：火星探路者 VxWorks；解决方案原本是有的，但开关被关掉了 → 反复重启 `[w6-1 1:11:42~1:17:58]`。
- 三种解法：临界区内**关中断**；**优先级天花板**（提到最高）；**优先级继承**（继承被它阻塞的高优先级进程的优先级）`[w6-1 1:14:03~1:16:31]`。

### 4.4 实例：Windows 线程调度 ★★

- 以**线程**为单位；动态优先级 + 抢占；32 级：0 = 零页线程（idle），1~15 可变（用户），16~31 实时（固定）`[w6-1 1:40:02]`。
- 用**时间配额**（一个数值，不是时间长度）代替时间片；可以给前台线程多分配额 `[w6-1 1:43:15]`。
- 用完配额**不降级**（和 MLFQ 不同）；被抢占回**队首**；实时线程被抢占后拿完整配额，可变优先级线程只用剩余配额 `[w6-1 1:47:04]`。
- 额外的调度时机：线程优先级改变、处理器亲和集合改变 `[w6-1 1:37:27]`。
- 防饥饿：I/O 完成提升优先级（上限 15）并减少配额；**平衡集管理器**每秒扫描，等太久（课上说 300 个时钟周期）的线程提到 15 级、给 4 倍配额，用完降回 `[w6-1 1:51:53~1:53:06]`。

### 4.5 多处理器调度与实时调度 ★★

- SMP vs NUMA；**全局队列**（负载均衡好，但要加锁、易成瓶颈）vs **每 CPU 队列**（无锁竞争，但要做负载均衡）`[w6-2 09:33]`。
- 三个问题：**负载均衡、亲和性、缓存一致性（MESI）**；负载均衡与亲和性**天然矛盾**（迁移 → cache/TLB 失效）`[w6-2 10:52~17:04]`。
- **任务窃取（work stealing）**：本地队列空了去偷别人的；Go 的 GMP 调度器也这么做 `[w6-2 20:04~21:07]`。
- 硬实时 vs 软实时 `[w6-2 24:15]`。
- **RM**（静态优先级）vs **EDF**（动态，截止期越近越优先；开销更大）`[w6-2 28:09~30:26]`。

**易错点**
- 课上说 RM "执行时间越短优先级越高"（课件原文也这么写），**准确说法是周期越短（速率越高）优先级越高**——"速率单调"名字就是这么来的 → 笔记 4.7。开卷时按"周期"答更稳。

### 4.6 实例：Linux 调度演化 ★★（CFS 不要求记忆）

- **Linux 2.4**：优先级由 nice + counter 算出；睡眠进程剩余的 counter 会叠加 → 偏好 I/O 型。
  - ★★★ 它的**缺点**（老师明说是考点）`[w6-2 43:08]`：① 可扩展性差（要遍历整个队列，开销随进程数增长）；② 高负载下性能差；③ 用"睡眠时间长"判断交互式进程不准确；④ **内核不可抢占**，高优先级实时进程来了不能立即抢占。
- **O(1)**：active / expired 两个按优先级分组的数组 + bitmap；active 空了**交换指针**；交互式进程用完时间片放回 active。缺点：公式复杂难懂、交互响应仍不好 `[w6-2 45:50~48:24]`。
- **SD（楼梯）/ RSDL**：逐级降级，防饥饿；RSDL 引入组配额 TG 和进程配额 TP，运行时间可预测 `[w6-2 49:04~55:06]`。
- **CFS**：只需掌握思想——每个进程有 **vruntime**（与实际运行时间成正比、与权重成反比），每次选 vruntime **最小**的进程，用**红黑树**组织，取最左节点 `[w6-2 1:08:07~1:15:48]`。
- **EEVDF**（课堂派作业）：在 CFS"公平"的基础上引入**延迟（lag / 虚拟截止时间）**这个因素。

**易错点（细节以笔记为准，开卷时别抄错）**
- nice 范围是 **-20 ~ 19**（转写稿里写成 -19~20），越小优先级越高。
- vruntime 增量 = 实际运行时间 × **NICE_0_LOAD（1024）/ 进程权重**（课上口述成"× nice 值 / 权重"）→ 笔记 4.9。
- Linux "实时进程"（`SCHED_FIFO`/`SCHED_RR`）的优先级一定高于普通进程，走单独的调度类 `[w6-2 32:07]`。

## 七、难点（需要多花时间串起来的地方）

1. **软硬件交接的精确边界**：硬件到底保存了哪些寄存器、何时换栈（x86 自动换栈 vs RISC-V 软件换栈），交接点是"硬件改 PC 跳到处理程序入口"。建议对照 x86 栈布局图和 xv6 `trapframe` 各画一遍。
2. **"状态转换—中断异常—调度时机"三者的对应**：给任意一个事件（fork、时钟中断、磁盘中断、`wait`、`exit`），能说出：从哪条路进内核 → 哪个进程状态怎么变 → 哪个队列怎么变 → 会不会触发调度 → 若可抢占会不会换人。这是分析题最常见的出法。
3. **fork + COW + exec 的数据结构变化**：`task_struct`/`mm_struct`/VMA/页表/物理页，每一步谁复制了、谁共享、谁被标成只读，哪一步发生页错误。
4. **线程实现方式的推导**：从"内核是否感知线程"这一个前提，推出阻塞行为、能否多核、切换开销、调度单位（以及用户级线程"显示 running 实际被阻塞"的状态现象）。
5. **调度算法的多维对比与 MLFQ 的策略选择**：没有标准答案的"问号题"，要写出选项、理由和代价（公平性 vs I/O 偏好 vs 开销）。
6. **利用率 / 周转时间的手算**：画甘特图，注意 I/O 期间 CPU 可以运行别的进程、抢占发生的时刻、时间片边界。
7. **Linux 调度器演化的"为什么"**：2.4 的缺点 → O(1) 怎么解决 → 为什么又被放弃 → SD/RSDL → CFS 换了思路（不再猜交互式，直接按权重分配公平份额）。按"问题 → 改进 → 新问题"的链条记，比记细节有用。
